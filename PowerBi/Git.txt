==============================
Git & Git Bash - دستورات پایه
==============================


--- دستورات پایه Git Bash ---

pwd
الان دقیقاً کجام؟
مسیر فعلی را نمایش می‌دهد.


ls
محتویات فولدر فعلی را نمایش می‌دهد.


cd FolderName
Change Directory
وارد فولدر موردنظر می‌شود.

مثال:
cd Seafood-Analytics


cd ..
یک فولدر به عقب برمی‌گردد.


rm FileName
فایل را از Working Directory حذف می‌کند.

مثال:
rm 1111.pbix



==============================
شروع کار با Git
==============================

git init
Git را در فولدر فعلی راه‌اندازی می‌کند.
یک فولدر مخفی به نام .git ایجاد می‌شود.
معمولاً برای هر پروژه فقط یک بار انجام می‌شود.


git status
وضعیت فعلی پروژه را نشان می‌دهد:
- چه فایل‌هایی تغییر کرده‌اند
- چه فایل‌هایی Stage شده‌اند
- چه فایل‌هایی Stage نشده‌اند


==============================
سه محیط اصلی Git
==============================

1) Working Directory
فایل‌هایی که در حال حاضر روی آن‌ها کار می‌کنیم.

        |
        | git add
        v

2) Staging Area
تغییراتی که برای Commit بعدی انتخاب کرده‌ایم.

        |
        | git commit
        v

3) Repository
تاریخچه تغییراتی که Commit کرده‌ایم.


خلاصه:

Working Directory
        |
     git add
        |
        v
Staging Area
        |
    git commit
        |
        v
Repository


==============================
Staging
==============================

git add FileName
تغییرات فایل را وارد Staging Area می‌کند.

مثال:
git add 1111.pbix


git add .
تمام تغییرات موجود را Stage می‌کند.


git restore --staged FileName
فایل را از Staging Area خارج می‌کند،
ولی خود فایل حذف نمی‌شود.

مثال:
git restore --staged 1111.pbix



==============================
Commit
==============================

git commit -m "Message"

تغییرات Stage شده را در Repository ثبت می‌کند.

-m یعنی Message

مثال:
git commit -m "Add 1111.pbix"


نکته:
Commit فایل را جابه‌جا نمی‌کند.
فقط وضعیت تغییرات را در تاریخچه Git ثبت می‌کند.



==============================
حذف فایل
==============================

روش اول:

rm FileName

فایل را از Working Directory حذف می‌کند.

بعد باید حذف را Stage کنیم:

git add FileName

و سپس:

git commit -m "Delete FileName"


روش راحت‌تر برای فایل‌هایی که Git از قبل Track می‌کند:

git rm FileName

این دستور:
1. فایل را حذف می‌کند.
2. حذف فایل را Stage می‌کند.

بعد:

git commit -m "Delete FileName"


مثال:

git rm 1111.pbix

git commit -m "Delete 1111.pbix"



==============================
Restore
==============================

git restore FileName

تغییرات Commit نشده فایل را کنار می‌گذارد
و نسخه ثبت‌شده را برمی‌گرداند.

مثال:

git restore 1111.pbix


هشدار:
ممکن است تغییرات Commit نشده فایل از بین برود.



==============================
تاریخچه Commitها
==============================

git log --oneline

تاریخچه Commitها را به صورت خلاصه
و هر Commit را در یک خط نمایش می‌دهد.


مثال خروجی:

7ab23cd (HEAD -> master) Delete 1111.pbix
94a72fb Add 1111.pbix


94a72fb
شناسه Commit است.


master
Branch فعلی است.


HEAD
موقعیت فعلی ما در تاریخچه Git را نشان می‌دهد.



==============================
دستورات مهم برای حفظ کردن
==============================

pwd
الان کجام؟


ls
اینجا چه فایل‌ها و فولدرهایی وجود دارد؟


cd FolderName
وارد فولدر شو.


cd ..
یک فولدر برگرد عقب.


rm FileName
فایل را حذف کن.


git init
Git را برای پروژه راه‌اندازی کن.


git status
وضعیت فعلی Git را ببین.


git add FileName
تغییر فایل را Stage کن.


git restore --staged FileName
فایل را از Stage خارج کن.


git commit -m "Message"
تغییرات Stage شده را ثبت کن.


git rm FileName
فایل را حذف کن و حذف را Stage کن.


git restore FileName
تغییر Commit نشده را برگردان.


git log --oneline
تاریخچه Commitها را خلاصه ببین.
